Help & conventions

The explorer is a static, browser-based reader for BMOPF case and result JSON. Start with a built-in example or drop in your own files, then select an asset to connect the views and inspector.

Quick start
  1. Choose a built-in example, open a case JSON, or drop a case into the drop zone. Single-wire opens first as the default overview.
  2. Use the Inventory or Class overview to select a bus or asset.
  3. Switch views to compare geographic placement, a compact single-wire overview, and terminal-level multi-wire detail.
  4. Attach a result JSON after loading a case to colour assets and inspect solution metrics.
Views

Geospatial uses supplied bus coordinates and line geometry. Buses without coordinates stay explicitly unplaced; synthetic built-in coordinates are labelled as illustrative.

Single-wire collapses phase conductors into an engineering-style overview. Heavy lines are busbars, paired coils are transformers, and open blades/dashed paths identify open switches.

Multi-wire expands terminal maps for a selected bus or device. Phase, neutral, and ground cues are labelled as well as patterned. Branches show their Π-model matrices when supported.

Diagnostics collects validation, bounds, residual, and solution-profile findings from the active result slice.

Visual conventions
  • Phase conductors use red/green/blue; neutral and ground use patterned grey lines with labels.
  • An open switch uses an open blade and a dashed connection. Out-of-service assets are faded.
  • Result overlays use green for nominal, amber for moderate, and red for high loading or voltage deviation; patterns and text repeat the meaning.
  • A faint dashed leader in Single-wire connects a manually moved symbol to its computed electrical anchor.
Data and units
  • Terminal maps are ordered: a pair such as 2→3 means source terminal 2 is connected to destination terminal 3.
  • Branch series entries are R+jX in absolute Ω. Linecode values in Ω/m are multiplied by the branch length.
  • Branch shunt G/B entries are absolute admittances in S and are shown as from/to Π half-sections only when nonzero.
  • Missing or unsupported semantics remain inspectable as raw properties and are called out rather than silently inferred.
Interaction and accessibility
  • Select assets in any view, follow Related links in the inspector, and use Back/Forward to retrace exploration.
  • In Single-wire, drag buses or device symbols. Bus positions and symbol overrides are stored locally for the active case/layout profile.
  • Use zoom, pan, Focus selection, and Fit / reset for the active SVG. Single-wire offers deterministic, force-directed, and optional ELK layouts, plus page-session Display options for hiding labels/arrows or showing selected labels only. Resize the details panel or table columns with pointer dragging; focused separators also respond to Arrow keys.
  • Keyboard users can Tab to assets, press Enter or Space to select, and use the Inventory search arrows plus Enter to jump to a ranked match.
Large cases and performance

Cases over the overview guidance (more than 500 buses or roughly 5,000 estimated SVG elements) prompt before full rendering. Focused views, Diagnostics, and the deterministic layout fallbacks remain available. Force-directed layout is self-contained; ELK is optional and may be slower or unavailable on very large graphs.

Provenance and limitations

This tool reads JSON without changing the source files. Matching case/result identities are verified when fingerprints are available; otherwise pairing is labelled unverified. Built-in cases are illustrative CC BY 4.0 fixtures, while reused cases retain their source licences.
